## 1. 设计方向

**交易终端（Trading Terminal）**：深色优先、信息高密度。

- **红涨绿跌**（A 股习惯）；金叉 = 红、死叉 = 绿；强调色琥珀金。
- 数字统一 `tabular-nums` 等宽对齐，价格 / PE / PB 可竖向直接对比。
- **深色 / 浅色双主题**：同一套 CSS 变量出两套主题，右上角切换，`localStorage` 记忆，默认深色。
- **原生控件必须跟随主题**：两套主题块各自声明 `color-scheme: dark` / `light`，否则 `<select>` 展开的
  option 弹层、滚动条、autofill 会按系统浅色渲染（暗色下白底浅灰字，几乎不可读，D-15）；
  `.select option` / `.ask-select option` 另需显式 `background-color` / `color`——弹层不吃父级变量，
  个别平台仍走系统配色。回归锁：`tests/test_theme_controls.py`。

### 4.1 页面结构与数据来源

模板形态以 `design-preview/screens/*.html` 为准（设计稿已评审通过），实施时以设计稿校对：

| 页面 | 结构要点 | 数据补充 |
| --- | --- | --- |
| 订单列表 | 4 项 KPI（总订单 / 监控中 / **触发告警** / 采集状态）+ chips 筛选 + 高密度表格 | 「触发告警」由 `StockMaster.count_alarm_active()` 提供 |
| 订单表单 | 四段式（标的信息 / 价格阈值 / 估值阈值 / 备注）+ **K 线图在主列**（仅编辑态）；右侧 rail 为 实时行情 / 填写提示 / 操作 | 三档阶梯的"距现价百分比"由前端按 `data-current` 实时计算；**只保留第 4 段一个备注框** |
| 告警设置 | 左标的列表 + 右多页签（价格 / PE / PB / **指标**，四个页签均可编辑） | 阈值覆盖的占位提示显示当前全局值 |
| 告警历史 | 4 项 KPI（今日触发 / 近 7 天 / 邮件送达 / 发送失败）+ 按天时间线 | 由 `StockAlarm.get_stats()` 提供 |
| 账户设置 | 左二级导航（个人资料 / 修改密码 / 通知偏好 / 退出登录）+ 单张卡片：头像头部（最后登录）、2×2 资料区（用户名 / 邮箱 / 手机号 / 默认基准指数）、告警通知四开关 + 收件人说明、修改密码区 | 基准候选 / 开关状态 / 收件人全部来自 `models/account_settings.py`，与监控发信同源 |

- `StockMaster.count_alarm_active()` 与列表 `is_alarm_active` **共用 `ALARM_ACTIVE_CONDITION`**，保证"列表高亮行数"与"KPI 触发告警数"永不漂移（回归用例 `tests/test_page_stats.py`）。
- 订单表单的监控状态下拉、K 线图、实时行情栏**仅在编辑态渲染**；新建态 rail 降级为填写提示。
- 订单表单**只有一个可见备注框**（第 4 段）。`stock_pe.memo` / `stock_pb.memo` 仍以隐藏字段回传原值——字段名一旦消失，后端 `request.form.get(..., '')` 会把已有备注清空；这两个字段的编辑入口在「告警设置」页（回归用例 `tests/test_form_render.py`）。
- K 线图悬停需显示该日全部 4 个值：`interaction.mode='index'` + `intersect:false`（默认 `nearest` 只显示一个数据集，看起来像"显示不全"）；接口返回 Decimal 字符串，绘图前必须转数值。
- 表格统一 `table-layout: fixed` + `<colgroup>` 定宽，宽列（如「标的」）吸收剩余宽度；**末列操作按钮需 `position: sticky; right: 0` 吸附右侧**，否则右对齐的按钮会被推到看不见的位置。
- **侧栏可折叠**：折叠控件（`data-side-toggle`）在「监控」组标题右侧，chevron 图标表示方向；折叠态由 `.shell.side-collapsed` 覆盖 `--sidebar-w`，与窄屏（≤1000px）共用同一套"只留图标"规则。
  两个坑：① 折叠时隐藏的是 `.nav-group-label` 里的 **`span`**，整块隐藏会把按钮一起弄没；② 导航项必须带 `title`，否则折叠后无从分辨功能。
- **侧栏分三组（对齐设计稿）**：「交易」（订单列表 / 添加订单 / 告警设置 / 告警历史）、「监控」（指标监控 / AI 分析）、「系统」（账户设置 / 退出登录）。
  每组是 `<div>`（组标题 + `nav`），`.sidebar` 的 `gap: 20px` 因此只落在组与组之间；品牌副标为 `Stock Monitor`。
  账户设置 / 退出登录是 GET `<a>`（侧栏不塞表单），顶栏头像下拉**保留**（那里还显示当前用户名）。
  见 [2026-10-23 侧栏导航分组](../archive/changes/2026-10-23-sidebar-groups.md)。
- **账户设置的开关与取值必须同源**：默认基准指数的候选、告警通知开关状态、告警收件人展示，
  全部来自 `models/account_settings.py` 的解析结果（与监控发信同一个函数），禁止在模板里另写一套默认值；
  通知开关用 `.notify-toggle`（原生 checkbox 隐藏 + `.status/.switch` 视觉），on 态由服务端渲染一次、
  再由 `theme.js` 跟随点击同步，禁用 JS 时也不会显示成"全关"。
- **基准采集状态要显式**：页面展示当前基准的「最新交易日」，没有就显示"尚无日线数据"——不把采集失败伪装成正常
  （恒生指数 `HKHSI` 尤其需要，当前环境无法联网实测四个雪球符号）。
- **Composer 的圆形按钮不换文案**：`data-submit-once` 默认会把提交按钮文案改成「提交中…」，
  圆形图标键会因此撑破，故带 `data-keep-content` 的按钮只禁用不改文案（`theme.js initSubmitOnce()`）。
- **「指标监控」徽标必须真实**：条数取 `StockAlarm.count_recent_indicator(24)`（`alarm_type='indicator'` 且 `alarm_time` 近 24h），
  由 `app.context_processor` 注入 `nav_badges`；为 0 时不渲染、查询失败降级为 0——**不许写死数字**。
  只在 `has_request_context()` 且已登录时查库（纯 app 上下文的 `render_template_string` 里碰 `session` 会直接抛错）。
- **K 线配色**：收盘价青绿实线，MA5/MA10/MA30 粉/蓝/黄虚线——颜色走 `theme.css` 的 `--kline-price / --kline-ma5 / --kline-ma10 / --kline-ma30`（暗色 400 档、亮色 600 档），**不得借用 `--up/--down/--info` 等语义色**；均线用 `borderDash: [6, 4]`。图表颜色在加载时取一次，切主题不重绘，需刷新。
- **静态资源必须带版本号**：模板里一律用 `{{ static_url('js/theme.js') }}`，**不要** `url_for('static', ...)`。
  Flask 对 static 的响应不带明确 `max-age`，浏览器会启发式缓存——改了 CSS/JS 用户仍拿到旧文件
  （真实故障：按钮是服务端渲染能看见，但旧 JS 里没有处理函数，点了没反应）。见
  [2026-10-22 静态资源加版本号](../changes/2026-10-22-static-version.md)。
- **操作必须有可见反馈**：只改数值不算反馈——数据常常和页面上已显示的一样（刷新只是重读库）。
  数值变化的单元格要短促高亮（`td.flash`），文案要区分"有更新"与"已是最新"。
- **表格底色只表达状态，不做装饰**：普通行不带底色；只有告警行（`tr[data-alarm="alarm"]`）与暂停行
  （`tr[data-status="inactive"]`）有专属底色，且是**多色渐变**（左起渐隐、终点透明，到右侧边缘收尾），
  告警行同时"流动 + 呼吸"。三个硬约束：呼吸只能改 `opacity`（渐变占了 `background`，改它会冲掉渐变）；
  多个动画必须改不同属性才能共存；sticky 操作列只能用等效实色且**不跑自己的动画**（渐变右缘已透明，
  跟着渐变会透视下层列）。
  曾给**所有行**铺过淡色底，用户反馈效果不好已回退——不要再加回去（有用例锁住"普通行不得有底色"）。
  sticky 操作列必须与行状态同源且动画参数一致，否则右侧出现不呼吸的死色块。
  见 [2026-10-22 告警行/暂停行专属背景](../changes/2026-10-22-row-state-bg.md)。
- **操作类按钮必须真的干活，但别打多余的外部请求**：如「刷新行情」（`POST /stock/refresh_quotes`）
  要真实刷新数值——但**只查库、不请求雪球**：监控线程在后台持续采集落库，库里本来就是最新的，
  页面刷新只是重新读取。范围限定**当前页**（前端传可见行的 `data-id`），不刷全表。
  首版曾做成"后台线程刷全部活跃订单 + 打雪球 API"，被用户纠正后回退，见
  [2026-10-22 刷新行情按钮](../changes/2026-10-22-refresh-quotes-button.md)。
- **系统状态必须是实时的**：侧栏底部 4 行（监控 / 交易时段 / 告警冷却 / 雪球）与顶栏 `pill live` 徽标，数据全部来自 `utils/system_status.build_system_status(monitor)`，由 `app.context_processor` 注入 `system_status` 做首屏渲染，`theme.js` 再按 `data-status-url` 每 30s 轮询 `/stock/api/system_status` 局部更新（页面隐藏时跳过）。
  **禁止写死文案**——模板只渲染，文案判定只在 `utils/system_status.py`。
- **运行状态要上色**：`build_system_status()` 的 `monitor` / `xueqiu` 增带 `tone`（`ok` / `bad`），
  模板渲染成 `status-ok`（**绿**）/ `status-bad`（**红**）——正常绿、异常红；
  颜色判定同样只在 `utils/system_status.py`，模板与 `theme.js` 都不做二次解读（否则首屏颜色对、轮询后不对）。
  两个坑：① 必须写 `.side-foot-row b.status-ok`，裸 `.status-ok` 会被 `.side-foot-row b`（特异性更高）的灰色压掉；
  ② 不要复用行情的 `up` / `down`——本项目红涨绿跌，`--up` 是红、`--down` 才是绿，直接拿来当"正常"会整反；
  用 `--ok` / `--bad` 语义别名。
  交易时段与告警冷却**刻意保持中性色**（它们是信息不是健康状态，"已收盘"变红会误导）。
  见 [2026-10-26 侧栏状态上色](../archive/changes/2026-10-26-sidebar-status-colors.md)。

- **指标监控页的数据缺失必须显性化**：缺快照 / 缺 52 周高低 / 缺 20 日收益的单元格一律渲染「—」「未采集」，
  **不得渲染成 0%**——0% 看起来像"很健康"，会被误读成正常。页面只读库内快照，不请求雪球；
  52 周区间条复用 `theme.css` 的 `range52-*`（低点 `--down-soft` → 高点 `--up-soft`）。
- **保存后回到原页签**：告警设置的四个页签共用同一 POST 路由，保存「指标告警」后重定向到
  `?tab=indicator`（`active_tab` 由服务端渲染 `on` / `hidden`），否则用户会被弹回「价格告警」，以为没保存成功。
- **AI 页四条硬约束**：① 未启用 / 未配置时只显示原因，并把「生成 / 追问 / 连通测试」等**会发请求**的入口
  `disabled`——「保存参数」是纯写库操作，始终可点；② 报告必须展示免责声明，且**用本地常量而不是模型返回的文案**
  （模型可能漏写或改写）；③ 页面**绝不出现密钥明文**，只显示 `sk-***ab` 这类脱敏状态；
  ④ 缺失数据（无快照 / 无置信度 / 无价格）一律渲染「—」，不得渲染成 `0` / `0.00%`。
- **列表行内的快捷入口复用「吸收剩余宽度」的那一列**，不新增列：订单列表的「标的」列用
  `.cell-with-action`（`justify-content: space-between`）两端对齐，右端放 `.row-ai` 小按钮（默认 muted / 透明底，
  行 hover 提亮、自身 hover 转 violet）。入口一律是 **GET `<a>` 链接**，列表里不塞表单（避免误提交）；
  链接必须指向**本行** id（`/stock/ai/?stock_id=<id>`），用例逐行比对防串标的。
  **列宽由定宽保证，不靠压缩**：订单表十列全定宽（标的列 300px），`table.table-orders { min-width: 1292px }`
  等于定宽之和——窗口再窄也只是 `.table-wrap` 横向滚动，**列宽永不反压**（D-13 教训：让 flex 收缩躲重叠，
  会把名称压到 0 宽、连省略号都不渲染）。另留三层 `min-width: 0` + 名称 `nowrap + ellipsis` 兜超长名称。
- **AI 页是「顶部搜索 + 工作台」，不是列表浏览页**：`.ai-hero`（居中大搜索框 + 状态 chips）+
  `.ai-work`（`minmax(0,1fr) / 320px`）。**页面不铺全量标的列表**——标的由 `?stock_id=`
  （订单列表行内「AI 分析」）或顶部搜索框确定；搜索框走 **`/stock/ai/api/search` 服务端真查库**
  （`data-ai-search` / `data-ai-input` / `data-ai-menu` + 220ms 防抖 + ↑↓/Enter/Esc），
  只在库里捞，不做前端过滤（`data-text-filter` 那套只覆盖已渲染行，标的多了就搜不到）。
  模型候选只能来自 `AI_MODELS`，维度 chips 用 `.dim` + `:has(input:checked)` 即时高亮，不依赖 JS 切类。
  两条硬约束：① **`q` 为空必须返回空列表**，不许退化成"返回全部"；② 搜索结果的 `url` 由服务端 `url_for` 生成，前端不拼。

## 6. 实施约束

- **现有路由与表单字段名保持不变**，后端视图层尽量少改；

- 不在模板中内联真实凭据或敏感配置。
