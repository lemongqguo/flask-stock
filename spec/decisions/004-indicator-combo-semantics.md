# ADR-004：指标告警采用「四项 AND 组合」而非单指标 OR

**状态**：已接受　|　**日期**：2026-10-23
**关联规格**：[006 指标监控](../current/006-stock-indicator.md)、[003 告警阈值与告警历史](../current/003-alarm-thresholds.md)
**关联变更**：[2026-10-23 指标告警改「四项同时满足」组合触发](../changes/2026-10-23-indicator-combo.md)

## 背景

初版（006 批次一）把四条指标实现为**四个独立信号**：任一条命中即各自发一条告警、各自一个冷却 key。
上线后用户反馈：「单个条件触发筛选出来的肯定不符合策略」。

根因是四条本身的宽松程度差异极大：

- 「52 周回撤 > 35%」在弱市里是**长期持续状态**，同时满足的标的一抓一大把；
- 「52 周新低 +5% 以内」同样覆盖面广；
- 四个条件取 OR，等价于"这几类里随便占一条就报"，结果集被最宽松的那条主导。

## 决策

**四条之间改为 AND**：`is_combo_hit(flags)` 全真才告警，一次组合命中只产出**一条**
`alarm_subtype='combo'` 的告警与一封邮件，冷却 key 收敛为单个 `indicator:combo`。

次要决策（由用户在确认环节选定）：

1. 组合命中后**只发一条总览邮件**（正文列出四项实测值与阈值），而不是四条各发一封——避免同一标的刷屏；
2. 指标监控页**只展示组合结论**（满足，已告警 / 未满足 / 未采集），撤掉四条独立命中角标与长期 / 短期分组 KPI；
3. 缺数据仍视为该条不满足 → 组合不成立 → 不告警。

四条 flag 列**照旧逐项落库**：组合是"告警口径"，单项是"数据事实"，排障时需要知道到底差哪一条。

## 代价

- **告警量大幅下降，属预期**：单指标（尤其回撤）再也不会单独通知。若将来需要"回撤预警"这类弱信号，
  应另开一条通道（比如只落库不发文），不要把 AND 放松回去。
- **判定口径变严，可能出现长期 0 告警**：这是策略选择，不是缺陷。
- 排障成本略增：页面不展示单项角标，"为什么没告警"要看库内 flag 列或自行按规则核算。
- 历史 `low52w` / `drawdown` / `rs20` / `rs5` 告警行留存在库，页面徽标需继续识别这四种取值（已实现）。

## 被否决的方案

- **保留 OR，仅降低单条阈值**：治标不治本，筛出的集合仍由最宽松条件主导。
- **"命中 N 条即告警"（可配 N）**：灵活但产品语义模糊，且需要一个新配置项，当前需求明确要"四项齐备"，先不做。
- **删除四条 flag 只留一个组合列**：丢失排障所需的数据事实，代价大于收益。
