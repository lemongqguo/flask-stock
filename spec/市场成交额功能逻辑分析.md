## 1. 功能概述

把 A 股**沪 / 深 / 北三市每日总成交额**（1990-12-19 至今）采集入库，并在「行情 → 市场成交额」页做看板展示：

- **采集**：东方财富 push2his 历史 K 线为主源，腾讯 newfqkline 为备源，主源异常自动降级；urllib 标准库实现，**无新依赖、无需 Token**。**2026-11-13 起智能取数**：库非空走增量（只取最近约 60 个交易日），库空 / 超窗 / `--full` 走全量（ADR-008）。
- **存储**：单表 `market_daily_turnover`，单位**亿元** `DECIMAL(18,4)`，`trade_date` 唯一键 + `ON DUPLICATE KEY UPDATE` 幂等 upsert。
- **展示**：页面**只读库**（加载 / 区间切换 / 60s 自动刷新都不打外部接口），只有「同步数据」按钮触发外部采集。
- **入库四路径**：页面同步按钮 / `flask sync-turnover`（日常同步）/ 监控线程自动同步（默认 3h，2026-11-13 起）、`flask import-turnover`（历史 CSV 全量导入），共用同一个幂等 upsert。

设计总原则（贯穿三层）：**「没采到」绝不伪造成 0**——缺失保留 `NULL`，前端渲染「—」；合计按缺失为 0 求和，但分量缺失本身如实留空。

### 2.2 数据流

```

  flask sync-turnover [--source ...] [--full] ───────┤

                                                     ▼

                                                     ▼
```

## 3. 统计口径（理解一切细节的前提）

| 市场 | 指数 | 东财 secid | 腾讯 secid | 口径说明 |
| --- | --- | --- | --- | --- |
| 沪市 | 上证指数 | `1.000001` | `sh000001` | 成交额字段即**全市场口径**（2020 年起含科创板） |
| 深市 | **深证成指** | `0.399001` | `sz399001` | 东财/腾讯该指数的成交额字段即**全市场口径**，**不是 500 只成分股之和**（2026-11-12 与用户 CSV 全量比对佐证） |
| 北证 | 北证50 | `0.899050` | `bj899050` | 2022-04-29 指数发布前无指数级成交额，对应日期留 `NULL` |

- **合计 = 三市之和（缺失按 0），不含基金、债券**。
- **单位链条**：东财返回**元** → 腾讯返回**万元**（×1e4 转元）→ 入库统一换算**亿元**（÷1e8，4 位小数）→ 展示 round 2（≥1 万亿前端换「万亿」）。
- **缺失语义**：北证 2022-04-29 前、深市 1991-07 开业前，分量列留 `NULL`；合计列 `NOT NULL`（缺失按 0 参与求和）。
- **盘中快照语义**：当日盘中同步得到的是**累计快照**，收盘后再次同步由 upsert 覆盖为终值——这是「当日允许覆盖」的设计动机。

> 分析备注：深市选**成指**而非综指（SZ399106）是口径断裂取舍——雪球口径下综指覆盖更全，但 example 在东财/腾讯口径下实测成指成交额即全市场，且用户历史 CSV 已按此口径拉好，换综指会与历史数据断裂（ADR-006「被否决的方案」）。

## 4. 数据源层：`utils/turnover_source.py`（254 行）

### 4.1 模块常量

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `FIRST_TRADE_DATE` | `"1990-12-19"` | 上交所开业日，腾讯翻页终止锚点 |
| `BSE_FIRST_DATE` | `"2022-04-29"` | 北证50 发布日。**分析备注：全项目仅此处定义，无任何代码引用**，属文档性常量；缺失语义实际由「源数据没有该日期 → None」自然实现 |
| `EASTMONEY_URL` | 见下 | 沪深主源 URL 模板（`secid` 拼接在末尾） |
| `EASTMONEY_BSE_URL` | 见下 | 北证专用 URL（完整 URL，无拼接） |
| `TENCENT_URL` | `https://proxy.finance.qq.com/ifzqgtimg/appstock/app/newfqkline/get?param=` | 备源 URL 前缀 |
| `TENCENT_PAGE_SIZE` | `2000` | 腾讯每页条数 |
| `TENCENT_MAX_PAGES` | `20` | 腾讯最大翻页数 → 单指数上限 40000 条（远超 1990 至今约 8800 个交易日） |
| `SOURCE_EASTMONEY` / `SOURCE_TENCENT` | `"东方财富"` / `"腾讯行情"` | 入库 `source` 列的中文标识 |
| `SOURCE_CHOICES` | `("auto", "eastmoney", "tencent")` | 合法数据源参数 |
| `BACKUP_PROTECT_DAYS` | `60` | 备源写入保护窗口（**交易日**，非自然日；仅全量路径生效） |
| `INCREMENTAL_DAYS` | `= BACKUP_PROTECT_DAYS`（60） | 增量同步窗口（交易日），与备源保护同值（ADR-008） |
| `INCREMENTAL_LOOKBACK_DAYS` | `100` | 东财增量 `beg` 的自然日回看量（≈60 交易日 + 节假日缓冲） |
| `INCREMENTAL_MAX_GAP_DAYS` | `100` | 库最新距今超过该自然日数 → 增量盖不住缺口，编排层回退全量 |

**东财 URL 参数逐项**（`push2his.eastmoney.com/api/qt/stock/kline/get`）：

- `klt=101`：日 K；`fqt=1`：前复权（对指数成交额无实际影响，沿用 example）。
- 沪深：`beg=19900101&end=20500101`（起止日期拉满）；**北证改用 `lmt=100000&end=20500101`**——注释明确：北证50 带 `beg` 参数会被服务端断开连接。
- `fields1=f1,f2,f3,f4,f5,f6`：基础字段；`fields2=f51,f56,f57`：K 线行字段 = 日期 / 成交量 / **成交额（元）**。

### 4.2 `http_json(url, headers=None, timeout=30)`

- urllib 标准库 `Request` + `urlopen`，默认头 `{"User-Agent": "Mozilla/5.0"}`，超时 30s，响应按 UTF-8 解码后 `json.loads`。
- 无重试、无代理、无凭据；异常（网络错误 / 非 JSON）原样上抛，由 `fetch_all` 的 auto 分支或视图层兜底。
- 分析备注：`app.prepare_runtime()` 还会设置全局 socket 默认超时（`Config.SOCKET_TIMEOUT`）作为线程挂死的兜底，与本函数的显式 30s 超时叠加生效。

### 4.3 主源：东方财富

**`parse_eastmoney_klines(url)`**

1. 带 `Referer: https://quote.eastmoney.com/` 请求（防盗链）。
2. 取 `payload["data"]["klines"]`（`or {}` / `or []` 防空）；**为空即抛 `RuntimeError("东财接口未返回数据：" + secid)`**——空数据视为源不可用，而非「没有成交」。
3. 每行按逗号切分，`{第0列日期: float(第2列成交额)}`，单位**元**。

**`fetch_eastmoney(since=None)`**：依次请求 `1.000001`（沪）、`0.399001`（深）、北证专用 URL，返回 `(沪, 深, 北)` 三个 `{日期: 元}` 字典。**任一指数失败即整体失败**（异常上抛，触发 auto 降级）。

- `since=None`（全量）：沪深 `beg=19900101`、北证 `lmt=100000`（原行为）。
- `since='YYYY-MM-DD'`（增量，ADR-008）：经 `_incremental_params(since)` 换算——沪深 `beg=since-100自然日`（`EASTMONEY_URL.replace("beg=19900101", ...)`）、北证 `lmt=N`（`EASTMONEY_BSE_URL.replace("lmt=100000", ...)`），N=max(60, 缺口自然日+10)。

### 4.4 备源：腾讯（向前翻页取全历史）

**`fetch_tencent_one(secid, count=None)`** 循环逻辑（全量最多 20 页；增量单页）：

1. 拼 `param={secid},day,,{end_date},{page_size},qfq`；首次 `end_date=""`（取最新一页）。`count=None`（全量）`page_size=2000`、最多 20 页；`count` 给定（增量）`page_size=count`、**只取 1 页即返**（解析后 `break`，不向前翻页）。
2. 取 `data[secid]` 节点的 **`qfqday` 优先、`day` 兜底**（前复权节点不存在时退到未复权节点）。
3. 空 rows → `break`（翻到头）。
4. 逐行：**第 9 个字段（`row[8]`）是成交额，单位万元**；仅当 `len(row) > 8 and row[8] not in ("", None)` 才收录，`float(row[8]) * 1e4` 转**元**。
5. 终止条件（满足任一即停）：
   - 本页最早日期 `earliest <= FIRST_TRADE_DATE`（已翻到 1990-12-19）；
   - 下一页锚点 `end_date = earliest - 1天` 已早于 `FIRST_TRADE_DATE`；
   - 达到 `TENCENT_MAX_PAGES = 20` 页上限。
6. 否则以 `earliest - 1天` 为新的 `end_date` **向更早翻页**，结果合并进同一字典。

**`fetch_tencent(since=None)`**：`sh000001` / `sz399001` / `bj899050` 各取一遍，返回三元组。`since` 给定时经 `_incremental_params` 取条数 N，三个 secid 均走 `count=N` 单页。

> 细节：翻页按**自然日减 1** 推进锚点，周末 / 节假日无数据不影响正确性（接口按「≤ end_date 的最近 N 条」返回）；字典合并天然去重，页间边界日期重复无害。

### 4.5 `validate(shanghai, shenzhen, beijing)` —— 源可用性判定

| 校验项 | 阈值 | 不达标行为 |
| --- | --- | --- |
| 沪市条数 | `>= 8000` | `RuntimeError("沪市数据条数异常：N")` |
| 深市条数 | `>= 8000` | 同上 |
| 北证条数 | `>= 500` | `RuntimeError("北证数据条数异常：N")` |
| 新鲜度 | `max(沪市日期)` 距今 `<= 10` 天 | `RuntimeError("数据过旧，最新日期：...")` |

细节：

- 条数阈值对应 1990 至今约 8800 个交易日的量级——**接口被截断 / 只返回部分历史时会被拦下**。
- 新鲜度**只查沪市**的最新日期（沪深同日历，北证 2022 年才发布不参与）；按 `datetime.now()` 的**自然日**差计算。
- 分析备注：自然日口径意味着春节 / 国庆长假（休市 9~10 天）会逼近 10 天阈值，极端长假叠加周末存在误判「数据过旧」的可能；当前阈值下历史长假未触发，但属于隐含边界。

**`validate_recent(shanghai, shenzhen, beijing, since)`** —— 增量校验（2026-11-13，ADR-008）：

| 校验项 | 阈值 | 不达标行为 |
| --- | --- | --- |
| 三市非空 | 沪 / 深 / 北各 `>= 1` 条 | `RuntimeError("X增量数据为空")` |
| 新鲜度 | `max(沪市日期)` 距今 `<= 10` 天 | `RuntimeError("数据过旧...")` |
| 源不落后 | `max(沪市日期) >= since`（库最新） | `RuntimeError("数据源最新日期...早于库内最新日期...")` |
| 窗口覆盖 | `min(沪市日期) <= since` | `RuntimeError("增量窗口未覆盖库内最新日期...")` |

**`_validate(sh, sz, bj, since)`**：分流器——`since=None` 走 `validate()`（全量），否则走 `validate_recent()`（增量）。增量不再要求 8000/500 条（只取最近区间，条数天然少），改用「非空 + 新鲜 + 不落后 + 覆盖」四道。

### 4.6 `fetch_all(source="auto", since=None)` —— 编排与降级

```
source 非法 → ValueError（可选 auto/eastmoney/tencent）
source == "tencent"   → fetch_tencent(since)，label=腾讯行情
source == "eastmoney" → fetch_eastmoney(since)，label=东方财富
source == "auto"      → try: fetch_eastmoney(since) + _validate(since)  → label=东方财富
                        except Exception: logger.warning(主源不可用，切备源)
                                          fetch_tencent(since)           → label=腾讯行情
末尾统一 _validate(since) → 返回 (沪, 深, 北, label)
```

细节：

- **auto 的降级触发面**：网络错误、空数据、条数不足、数据过旧——任何 `Exception` 都切备源（`except Exception` 宽捕获）。
- **校验次数**：auto + 东财成功路径 `_validate` 执行**两次**（try 内一次、末尾一次，幂等无副作用）；显式指定源与 auto 降级路径只在末尾校验一次。**备源数据同样必须过校验**，两源都失败则 `RuntimeError` 上抛。`since` 透传两源，增量模式下降级编排不变。
- 显式 `eastmoney` / `tencent` **不降级**：指定源失败即失败（CLI 排障用途）。
- 返回的 label 是中文名，直接作为入库 `source` 列值与页面徽标文案。

### 4.7 `build_rows(shanghai, shenzhen, beijing)` —— 组装入库行

1. `all_dates()` = 三市日期**并集排序**（`sorted(set|set|set)`）——任一市场有数据的交易日都会成行。
2. 逐日取三市值（`.get(day)`，缺为 `None`）：
   - 分量：`None if x is None else round(x / 1e8, 4)` —— **元 → 亿元，4 位小数，缺失留 None**。
   - 合计：`round(((sh or 0.0) + (sz or 0.0) + (bj or 0.0)) / 1e8, 4)` —— **用原始元值求和后再换算舍入**，缺失按 0。
3. 行结构：`{trade_date, sh_amount, sz_amount, bj_amount, total_amount}`（**不含 source**，source 由写入方统一传入）。

> 细节（舍入顺序）：合计是「原始值求和 → 换算 → round 4」，分量是「各自换算 → round 4」。因此**合计与分量舍入后的和可能相差最多约 0.0002 亿**——这正是 CSV 校验容差 `TOTAL_TOLERANCE = 0.0002` 的数学来源（三个分量各 ±0.00005 + 合计 ±0.00005）。
> 空输入返回 `[]`（有单测锁定）。

## 5. 模型层：`models/market_turnover.py`（288 行）

### 5.1 数据表 `market_daily_turnover`（`database.py` 幂等建表）

```sql
CREATE TABLE IF NOT EXISTS market_daily_turnover (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    trade_date DATE NOT NULL,
    sh_amount DECIMAL(18,4) NULL,
    sz_amount DECIMAL(18,4) NULL,
    bj_amount DECIMAL(18,4) NULL,
    total_amount DECIMAL(18,4) NOT NULL,
    source VARCHAR(16) NOT NULL DEFAULT '',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_turnover_date (trade_date)
)
```

- **亿元 + 4 位小数**与历史 CSV 完全一致，导入无损（ADR-006 否决了「存元」方案：换算引入舍入误差、展示还要再除）。
- `trade_date` 唯一键是幂等 upsert 的基础；`updated_at ON UPDATE` 自动记录每次覆盖时间（页面「更新于」取全表 `MAX(updated_at)`）。
- `source` 取值三种：`CSV导入` / `东方财富` / `腾讯行情`。
- 新表无存量迁移；`CREATE TABLE IF NOT EXISTS` 幂等。

### 5.2 模块常量

| 常量 | 值 | 用途 |
| --- | --- | --- |
| `DEFAULT_CSV_PATH` | `<项目根>/example/A股每日成交额_1990至今.csv` | `import_csv` 默认路径。**分析备注：当前工作区不存在 `example/` 目录**（该目录是用户本地实测产物，未入库），默认路径导入前需确认文件存在或显式传路径 |
| `CSV_COLUMNS` | `('日期','沪市成交额(亿元)','深市成交额(亿元)','北证成交额(亿元)','合计成交额(亿元)')` | example 固定表头，**顺序敏感**（元组全等比对） |
| `TOTAL_TOLERANCE` | `0.0002`（亿元） | 合计 = 分量和的舍入容差 |
| `SOURCE_CSV` | `'CSV导入'` | CSV 路径的 source 标识 |
| `_UPSERT_FIELDS` | `('sh_amount','sz_amount','bj_amount','total_amount','source')` | 可更新字段白名单：`trade_date` 是唯一键不参与 UPDATE；`created_at` 保留首次写入时间 |

### 5.3 `parse_csv_rows(path)` —— CSV 解析 + 整体校验（纯函数）

**任何一行不合法即整体拒绝（`ValueError`），不做部分导入**——「历史数据宁可不进，不可进一半」。

校验链（按执行顺序）：

1. 文件存在（`os.path.isfile`）。
2. 表头与 `CSV_COLUMNS` **元组全等**（列名、顺序都不能差）。
3. 逐行（行号从 2 起，报错带行号）：
   - 日期 `strptime('%Y-%m-%d')` 严格格式；`seen` 集合查重（**文件内日期重复也拒绝**）。
   - 三市分量：空串 → `None`（北证早期 / 深市开业前，留空不伪造 0）；否则 `float` 解析，**负数拒绝**。
   - 合计：必须数值、非负；`|合计 - Σ(分量 or 0)| > 0.0002` 拒绝。
4. 全部通过但**无数据行**（只有表头）→ 拒绝。

返回行结构与 `build_rows` 同构（不含 source）。注意：**CSV 的合计直接采用文件值**（容差内认可），不像 `build_rows` 那样重算——尊重 example 产物的原始舍入。

### 5.4 `dashboard_payload(rows, updated_at=None)` —— 看板组装（纯函数）

输入约定：**按日期升序**的行（由 `get_history` 保证）；空列表返回 `None`。

内部工具：`_f` = `None` 保留、否则 `round(float, 2)`（展示统一 2 位小数）；`_day` = `str(value)[:10]`（兼容 `date` 对象与字符串）。

| 输出字段 | 计算逻辑 |
| --- | --- |
| `updated_at` | 透传（调用方给全表 `MAX(updated_at)`），缺省 `''` |
| `source` | **最新一行**的 source（不是全库统一来源——混合来源库显示最近写入源） |
| `latest` | `rows[-1]` 的 date / sh / sz / bj / total（round 2，缺失 None） |
| `stats.rank` | `1 + count(total > 最新total)` —— **并列名次制**（相同合计同名次，如 1,2,2,4） |
| `stats.days` | 总行数（库内交易日总数） |
| `stats.peak_date` / `peak_total` | `max(rows, key=total)`；并列时取**先出现**者（`max` 语义） |
| `stats.avg20` | **最近 20 行**合计的算术平均（不足 20 按实际行数），round 2；只算合计，不分市场 |
| `history` | 全量数组的数组：`[date, sh, sz, bj, total]`，缺失 None（前端渲染「—」） |

结构与 example 的 `data.json` 同构；纯函数不碰数据库，单测直接喂字典列表。

### 5.5 `MarketDailyTurnover` 类方法

**`count()`**：`SELECT COUNT(*)`，备源保护判定专用（库空 / 非空）。

**`get_history(start_date=None, end_date=None)`**：全字段（含 source）按 `trade_date ASC`；可选区间过滤，`%s` 参数化防注入。页面与统计共用。

**`get_latest()`**：`ORDER BY trade_date DESC LIMIT 1`（含 updated_at）。**2026-11-13 起成为增量锚点**——`sync_from_source` 用它取库内最新交易日判定增量/全量（此前无调用方，属预留助手，现已启用）。

**`upsert_rows(rows, source)`** —— 四条写入路径的唯一入口：

```sql
INSERT INTO market_daily_turnover (trade_date, sh_amount, sz_amount, bj_amount, total_amount, source)
VALUES (%s,%s,%s,%s,%s,%s)
ON DUPLICATE KEY UPDATE sh_amount=VALUES(sh_amount), ... , source=VALUES(source)
```

- **`execute_many` 单连接批量执行**（`BaseModel.execute_many`：一次取连接 → `executemany` → 一次 commit；失败 rollback）。注释明确动机：8807 行逐条写会把连接占用放大几千倍（D-07 连接池排队教训）。
- 幂等语义：重复执行不增行；**当日盘中快照允许被收盘终值覆盖**；`created_at` 保留首次写入，`updated_at` 自动刷新。
- 返回值是 MySQL 受影响行数语义：**插入计 1、更新计 2**（值未变更计 0），仅供日志参考，不等于写入行数。
- 空 rows 直接返回 0，不发 SQL。

**`sync_from_source(source='auto', full=False)`** —— 日常同步编排（页面按钮 / CLI / 监控线程共用）：

1. **判定取数模式**（2026-11-13，ADR-008）：`full=False` 时查 `get_latest()`——
   - 库非空且最新日期距今 `<= INCREMENTAL_MAX_GAP_DAYS`（100 自然日）→ `since = 库最新交易日`（**增量**）；
   - 库最新距今 `> 100` 自然日 → 超窗，`logger.info` 后 `since=None`（**回退全量**）；
   - 库空（`get_latest()` 返回 None）或 `full=True` → `since=None`（**全量**；`full=True` 时短路不查库）。
2. `turnover_source.fetch_all(source, since=since)` 取数 + 校验（auto 自动降级，增量走 `validate_recent`）。
3. `build_rows` 组装（亿元行）。
4. **备源 60 日写入保护（仅全量路径）**（ADR-006，对齐 example `write_csv` 的 protect 语义）：
   - 触发条件**四者同时满足**：`since is None`（全量）**且** `label == 腾讯行情` **且** rows 非空 **且** `count() > 0`（库非空）。
   - `protected_before = rows[-60:][0]['trade_date']` —— 取**采集结果**倒数第 60 个交易日的日期（不是库里的日期）；只保留 `trade_date >= protected_before` 的行。
   - 动机：腾讯早年历史与东财口径差异大（2026-11-12 全量比对：早年 9267 处差异，近 60 个交易日除当日盘中快照外零差异），**保护 CSV 导入的东财口径历史不被备源污染**。
   - 库为空时备源可**全量写入**（口径风险在页面空态指引与文档注明）。
   - **增量路径不叠加裁剪**：取数窗口本身即保护（只取最近约 60 个交易日），`protected_before` 恒为 None。
   - 细节：采集结果不足 60 行时 `rows[-60:]` 即全部，`protected_before` 为首日，过滤后无实际裁剪。
5. `upsert_rows(rows, label)` 写入。
6. 返回 summary：`{source, mode, days, affected, protected_before, start_date, end_date}`（`mode='incremental' if since else 'full'`；空 rows 时起止日期为 `None`），并 `logger.info`。

**`import_csv(path=None)`**：默认 `DEFAULT_CSV_PATH` → `parse_csv_rows` 整体校验 → `upsert_rows(rows, 'CSV导入')` → summary（**无 `protected_before` 键**）+ 日志。幂等可重复执行。

**`build_dashboard()`**：`get_history()` 全量升序 → 空则 `None` → 查 `MAX(updated_at)`（`datetime` 实例格式化为 `'%Y-%m-%d %H:%M:%S'`）→ `dashboard_payload(rows, updated_at)`。

### 6.1 同步冷却机制（逐细节）

```python
_last_sync_at = 0.0                      # 模块级进程内存
now = time.monotonic()                   # 单调时钟，不受系统时间调整影响
wait = Config.TURNOVER_SYNC_COOLDOWN - (now - _last_sync_at)
if _last_sync_at and wait > 0:           # 首次（0.0）永远放行
    return 429, '同步过于频繁，请 %d 秒后再试' % (int(wait) + 1)
_last_sync_at = now                      # ★ 调用前置位：失败也计入冷却
```

- **冷却起点在调用前置位**——失败也冷却，防止「失败 → 立刻重试 → 再失败」的重试风暴打爆外部数据源。
- 429 文案秒数 `int(wait) + 1` 向上取整，避免「请 0 秒后再试」。
- 页面按钮**固定 `auto`**，不能选源（选源能力只暴露在 CLI）。
- 异常统一 502 + 通用文案（「数据源不可用或数据校验未通过，详见日志」），**不向客户端泄露内部细节**；堆栈进日志。
- **冷却只管页面按钮**：`flask sync-turnover` CLI 不经过视图，无冷却约束。
- 进程内存状态 → **多进程部署会失效**；项目强制单进程（gunicorn `workers=1`，与告警冷却 T-02 同类约定）。
- 分析备注：冷却判定与置位之间无锁，gthread 多线程下两个并发请求理论上可同过冷却检查（竞态窗口极小）；单进程 + 按钮 disable 前端兜底，实际风险可忽略。

### 6.2 视图「薄」的体现

校验（登录 / 冷却）→ 模型（取数 / 入库 / 统计）→ 渲染或 JSON，视图内无任何口径与 SQL 逻辑。
分析备注：首屏 `page()` 与前端首次 `api_turnover` 各调一次 `build_dashboard()`（全量历史查两次）——一次为服务端空态判断、一次为前端数据，是有意的职责分离而非缓存遗漏。

### 7.3 数据加载与自动刷新

- `load()`：`fetch(apiUrl + '?t=' + Date.now(), {cache:'no-store', headers:{X-Requested-With}})` —— 双重防缓存。
- `data.empty` / 无 history → 直接返回（不渲染假数据）。
- **`updated_at === lastStamp` 则跳过重绘**——60s 轮询但数据未变时零 DOM/画布开销。
- 网络异常：**保留上一次画面**；仅首载失败才显示错误提示层。

- `render()`：更新 hero / 指标卡；「较前一交易日」= `(末日合计 - 前日合计) / 前日合计 × 100`，带 `+` 号与 `up/down`  class（**全页唯一用涨跌语义色的地方**）；不足 2 行显示「—」。

**交互三件套**：

- **滚轮缩放**：`preventDefault`（`passive:false`）；缩放因子 1.2；**以光标位置为锚点**（保持光标下的数据点不动）；窗口下限 `MIN_POINTS = 20`、上限全量。

## 11. 关键设计取舍（ADR 摘要）

### ADR-006：数据源、口径与存储

- **取**：东财主源 + 腾讯备源（复用 example，无 Token）；深市用深证成指（实测即全市场口径）；亿元 `DECIMAL(18,4)` 新表；备源 60 日保护。
- **否决**：
  - **雪球接口**（项目现有 pysnowball）：已实测 `quote_detail`/`kline` 可取沪深成交额（SH000001 + SZ399106），但用户明确指定 example 口径；雪球历史深度仅约 6 年+，拿不到 1990 全量；北证50 可用性未验证；Token 会过期。
  - **深证综指 SZ399106**：雪球口径下更全，但与用户 CSV 的东财/腾讯口径断裂。
  - **复用 `stock_bench_kline` 加 amount 列**：基准收盘价与市场级日频成交额语义混杂，新表更干净、零迁移。
  - **金额存「元」**：与 CSV 亿元 4 位小数换算引入舍入误差，展示还要再除。

### ADR-007：自绘 canvas

- **取**：移植用户模板自绘 canvas（零依赖、离线可用、交互原样）；Chart.js 4.4.1 仅保留 K 线页。
- **否决**：Chart.js + zoom 插件（新 CDN 依赖、手感差距）；ECharts（重依赖，与 ADR-002 去 CDN 方向冲突）。
- **代价**：约 300 行绘制代码自维护（契约测试 + 浏览器验证缓解）；明细表移除（分市场数值进 tooltip）。**2026-11-13 修订**：分市场走势线已按用户要求加回（三条分量细线 + 轴下图例，见 `changes/2026-11-13-turnover-chart-component-lines.md`），自绘 canvas 决策本身不变。

### ADR-008：增量窗口与监控线程自动同步（2026-11-13）

- **取**：增量窗口约 60 交易日（与备源保护统一语义）；东财动态 beg / 北证 lmt / 腾讯 count 单页；校验分流 `validate_recent`；监控线程 `_maybe_sync_turnover()` 默认 3h（失败也计间隔、空库跳过、退避前调用）；页面按钮智能模式；全量只留 CLI `--full`。
- **否决**：每次全量（日常数据量放大两个数量级，用户否决）；只取当天（漏同步出缺口、盘中快照无法覆盖、近几天历史修正不收敛）；外部 cron（部署依赖、状态不可见，作备选）；独立调度线程（与现有旁路任务挂主循环结构重复）。
- **代价**：窗口外历史修正发现不了（靠 `--full` 月度校准）；增量依赖库内最新日期正确（污染时校验判源不可用、不静默写错）；东财增量路径本机未验证；监控轮内联阻塞有界（30s 超时兜底）。

## 12. 已知限制与风险（规格 §8 + ADR-006 / ADR-008 代价）

1. **本机网络东财不可达**（2026-11-12 实测 `RemoteDisconnected`）：日常路径实际是**腾讯备源 + 60 日保护**；历史全量依赖 CSV 导入（东财口径）。东财成功路径未在本环境验证。
2. **北证口径缺口**：北交所 2021-11-15 开市 ~ 2022-04-29 指数发布前的成交额无法从指数级接口获得，该区间合计**不含北交所**，页面与文档显式注明，不伪造。
3. **口径依赖数据源字段语义**：「指数成交额字段即全市场」是事实依赖，东财/腾讯若调整口径合计会失真；缓解靠 `validate()` + 页面展示数据源与更新时间。
4. **冷却为进程内存**：多进程部署失效（项目强制 gunicorn `workers=1`）。
5. **盘中快照**：当日盘中同步值是累计快照，收盘后需再次同步覆盖为终值。
6. **增量窗口外的历史修正发现不了**（2026-11-13，ADR-008）：60 交易日以前的源数据修正增量不可见，靠 `flask sync-turnover --full` 月度校准兜底。
7. **增量依赖库内最新日期正确**：库被污染（未来日期）时「源最新 ≥ 库最新」校验判源不可用，同步失败进日志、不静默写错；修复走 `--full` 或 CSV 重导。
8. **自动同步空库不初始化**：监控线程默认 3h 增量同步，但空库跳过——历史全量仍需 CSV 导入或首次手动同步；自动同步状态仅日志 + `get_status()` 字段，未接 UI（T-05 范畴）。

### 分析备注（代码阅读补充，非既有文档结论）

- `BSE_FIRST_DATE` 常量定义后无引用（文档性常量）；`MarketDailyTurnover.get_latest()` 原为预留助手，**2026-11-13 起被 `sync_from_source` 用作增量锚点**。
- 当前工作区**不存在 `example/` 目录**，`flask import-turnover` 默认路径会因文件不存在被整体拒绝——需先放入用户实测 CSV 或显式传路径。
- `validate()` 新鲜度按**自然日**（≤10 天）且只查沪市：超长休市（春节+周末）理论上可能逼近阈值误判，属隐含边界。
- 首屏 `page()` + 首次 `api_turnover` 各做一次全量历史查询（职责分离的有意为之）；60s 轮询每次传输全量 history（约 8800+ 行 JSON），无增量协议——靠 `updated_at` 比对跳过重绘，但网络传输是全量的。
- 冷却判定与置位无锁，gthread 下存在理论竞态窗口（前端按钮 disable + 单进程部署兜底）。
- `build_rows` 合计用原始元值求和后舍入，与分量各自舍入的和可有 ≤0.0002 亿差异——与 CSV 容差同源，属预期行为而非缺陷。
