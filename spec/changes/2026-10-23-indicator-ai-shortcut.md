## 1. 问题与动机

订单列表每行标的右端已有「AI 分析」快捷入口（[2026-10-22 订单列表 AI 快捷入口](./2026-10-22-list-ai-shortcut.md)），
指标监控页同样以标的为行单位，用户在指标页看到候选标的时需要手动搜索才能进 AI 页，入口不对齐。

## 2. 变更类型

- [x] **新增能力**：新场景复用既有能力，不改变任何判定 / 告警口径
- [ ] 缺陷修复 / 行为变更 / 技术重构

## 3. 旧约定 → 新约定

| 项 | 旧约定 | 新约定 |
| --- | --- | --- |
| 指标页「标的」列 | 只有名称 + 代码 | 名称/代码靠左，右端加「AI 分析」ghost 按钮（与订单列表同款 `.cell-with-action` / `.row-ai`） |
| 跳转 | 无 | `GET /stock/ai/?stock_id=<本行 id>`（`url_for('ai.page', stock_id=...)`），**每行指本行** |
| 列结构 | 不变 | **不新增列**，入口复用「标的」列的剩余宽度 |

告警 / 判定 / 采集逻辑零改动。

## 4. 影响面

- 涉及模块/文件：`templates/indicator_list.html`（标的单元格）、`tests/test_indicator_page.py`（新增 3 个用例）
- 涉及数据表 / 是否需要迁移：无
- 是否影响既有数据：否
- 是否需要新增/修改配置：否

## 5. 实施要点

- 完全复用订单列表的既有样式与三层 `min-width:0` 收缩规则（`static/css/theme.css` 全局类，零新增 CSS）；
- 入口为纯 GET 链接（不是表单），与订单列表一致。
