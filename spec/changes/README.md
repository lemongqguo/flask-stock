# 变更记录（Changes）

> 一次变更 = 一个目录。这里存放的是"**这次准备改哪里**"，合入后差异并入 `../current/`，本目录的记录转入 `../archive/`。
> 规范依据：[`../rules/spec-maintenance.md`](../rules/spec-maintenance.md)

---

## 目录约定

```
spec/changes/
├── README.md
├── _TEMPLATE.md                     # 变更记录模板（本身不是变更）
└── NNN-slug/                        # 一次变更一个目录，编号三位递增、只增不复用
    └── change.md                    # 变更记录正文
```

编号 `NNN` 全局递增（与 `../current/` 的规格编号共用一套序号空间便于追溯？**否**——两者独立编号，
变更编号只保证唯一与递增即可，正文中用链接指向受影响的规格）。

## 一次变更的生命周期

| 阶段 | 动作 | 文件状态 |
| --- | --- | --- |
| 1. 提出 | 复制 `_TEMPLATE.md` 为 `NNN-slug/change.md`，写明问题与拟改行为 | `提案` |
| 2. 确认 | 与需求方确认新约定；区分"实现不符原约定"还是"产品要改行为" | `已确认` |
| 3. 实施 | 改代码；若属"实现不符"，补回归测试；若属"行为变更"，同步调整测试期望 | `进行中` |
| 4. 验证 | 按记录中的验证范围实际跑一遍，填写验证结果 | `已验证` |
| 5. 合入 | 把差异写入 `../current/` 对应规格；更新 `../PROGRESS.md` 与 `../README.md` | `已合入` |
| 6. 归档 | 整个 `NNN-slug/` 目录移入 `../archive/changes/` | 归档完成 |

**只有第 5 步完成后，新约定才算"当前有效"。** 未合入的变更不得直接改 `current/`。

## 命名规范

- 目录名：`NNN-slug`，slug 用小写英文连字符，如 `006-alarm-cooldown`。
- 编号不复用、不删除；被放弃的变更状态标为 `已废弃` 并原样保留在归档中。
