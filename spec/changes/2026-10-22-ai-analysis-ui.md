## 1. 问题与动机

首次交付的 `/stock/ai/` 页把「状态 KPI + 报告 + 追问 + 参数」全部堆在右侧单列里，与设计系统
（`design-preview/screens/ai.html`，三栏 `.ai-layout`）不一致：标的列表挤在两栏布局的左半边，
参数与历史没有落位，标的超过十几只就得靠滚轮硬找；同时缺三样用户明确要求的东西：

1. **标的搜索**：91 只标的只能上下翻；
2. **模型选择**：`AI_MODEL` 只能改环境变量重启才生效，多模型对比无从谈起；
3. **分析维度**：只能整体分析，无法指定「只看估值和风险」。

改版过程中还发现一个**真实缺陷**（见 §3 第 4 条）：追问时把 `system` 全文当数据块拼进了用户消息，
真正的「标的 + 数据」反而没进提示词——追问只能靠上一轮报告里的数字回答。

## 3. 旧约定 → 新约定

| 项 | 旧约定 | 新约定 |
| --- | --- | --- |
| 页面布局 | 两栏（标的 rail + 内容），KPI 卡占顶部 | **三栏** `.ai-layout`：左「标的（可搜索）」/ 中「报告」/ 右「参数 + 快照 + 历史」；KPI 压成页头 pill |
| 标的筛选 | 无，全量 200 只直接铺开 | 左栏搜索框，**前端即时过滤**（名称 / 代码，`data-search`），列表来自一次性加载（≤200 只） |
| 模型 | 只认环境变量 `AI_MODEL` | `AI_MODELS`（逗号分隔）作为候选清单，页面下拉可选，**`AI_MODEL` 始终排第一**；选中的模型随请求下发并落库 `stock_ai_report.model` |
| 分析维度 | 无此概念 | 5 个维度（估值 / 技术面 / 相对强弱 / 52 周位置 / 风险），可多选；随提示词下发并落库 `content_json.dimensions` |
| 参数保存 | 温度 / 上限 / 引用范围 / 开关 | 增加 `model` + `dimensions`（`stock_ai_config` 新增两列，留空 = 跟随环境变量 / 全维度） |
| 追问提示词 | 用户消息里贴的是 `SYSTEM_PROMPT` 全文，数据块丢失 | 用户消息以「标的：…」开头，包含标的 + 数据 + 上一轮 JSON + 追问 |

**维度只取有数据支撑的五个**：设计稿里的「基本面 / 消息面」在本系统没有数据源，放出来只会让模型编，
故不提供（取舍记录见本文，不单开 decision）。

- 涉及数据表 / 是否需要迁移：`stock_ai_config` 增 `model VARCHAR(64)`、`dimensions VARCHAR(128)`；

- 是否影响既有数据：不影响。存量报告 `content_json` 无 `dimensions` 键，页面按「不显示维度块」降级
- 是否需要新增/修改配置：新增 `AI_MODELS`（可选，留空则只有 `AI_MODEL` 一项）

## 5. 实施要点

1. **模型白名单服务端二次校验**：下拉是前端渲染的，`model` 参数必须再校验一次（`is_allowed_model`），
   否则任何人可以 POST 任意模型名把请求打到未知模型上。非法模型直接拒绝，不静默回退。
2. **维度缺省语义**：表单没带 → 用参数面板保存的默认值；默认值为空 → 全维度。
3. **维度必须真进提示词**：`build_messages(context, dimension_labels)` 追加
   「本次要求的分析维度：…；每个维度至少给一条结论；该维度数据缺失就写「数据不足」，不要外推」。
4. **快照取值一律 `.get()`**：模板里 `snapshot.pct_from_low52w` 在列缺失时会让整页 500（实测踩到），
   改为 `.get()` + 「—」兜底；缺失值绝不渲染成 `0.00%`。
5. **价格来自 `StockIndicator.get_latest_batch()`**：一次 IN 查询同时喂左栏价格与右栏快照，不逐标查询。
6. **搜索是前端过滤**：数据已在页面上，本地过滤比每次都请求服务端快；代价是只覆盖已加载的前 200 只（已记入限制）。
7. **未启用只禁「会发请求」的入口**：生成分析 / 追问 / 连通测试 `disabled`，**保存参数仍可点**（纯写库）。
