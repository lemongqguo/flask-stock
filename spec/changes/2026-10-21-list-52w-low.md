# 变更：订单列表新增「52周最低」列

| 项 | 内容 |
| --- | --- |
| 状态 | **已合入** |
| 类型 | 新增能力（展示字段） |
| 触发 | 用户要求：现价与卖出价之间加一列「52周最低股价」 |
| 关联规格 | [002 股票订单管理](../current/002-stock-order.md)（3.1 列表节）、[005 K线与信号](../current/005-kline-signal.md)（数据来源） |
| 验证 | 全量 **217 用例通过**（新增 `tests/test_low_52w.py` 7 个，含真实库查询与列位断言）；列表页渲染核对 10 列、数值与直接 MIN 查询一致 |

## 1. 旧约定 → 新约定

| 项 | 旧 | 新 |
| --- | --- | --- |
| 列表列 | 标的 / PE / PB / 现价 / 卖出价 / 信号 / 状态 / 创建时间 / 操作 | **标的 / 现价 / 52周最低 / 卖出价 / PE / PB / 信号 / 状态 / 创建时间 / 操作**（共 10 列，价格类字段前置、估值类后置，顺序由用户指定） |
| 取值口径 | — | 近 **365 天** `stock_kline.low_price` 的 `MIN()`；无数据（12/92 个订单无近一年 K 线）显示 `—` |
| 查询方式 | — | **一次批量查询**（`GROUP BY stock_master_id`）取本页全部订单，不逐行查 |

## 2. 数据来源与前提

- 取自 `stock_kline.low_price`：库内 11389 行**全部非空**，近 365 天 11309 行，覆盖 80 / 92 个订单；
- 数据正确性依赖监控采集的 K 线；若某订单近期未采集，该列显示 `—`（不是 0，避免误读为"股价为 0"）；
- 口径按**自然日 365 天**近似 52 周（交易日约 250 天，用自然日更直观且不漏数据）。

## 3. 影响面

- `models/stock_kline.py`：新增 `get_low_52w_batch(stock_master_ids)`；
- `views/stock_orders.py`：`stock_list` 里批量取数并注入每行 `low_52w`；
- `templates/stock_order_list.html`：colgroup + th + td 各加 1 列，表格 `min-width` 1060 → 1160；
- 不改采集逻辑、不改告警判定（该列仅展示）。

## 4. 安全约束

- `IN` 子句的占位符由 `', '.join(['%s'] * len(ids))` 生成，值一律参数化，不拼用户输入；
- 查询失败 `logger.exception` 并返回空 dict，列表降级为全 `—`，**不让整页 500**。

## 5. 验证范围

- `get_low_52w_batch`：空列表返回 `{}`（纯逻辑）；
- 真实库批量查询：返回 dict、已知订单（宁德时代 285.17 / 泸州老窖 68.14）数值正确；
- 列表页渲染：10 列一致、该列出现在现价与卖出价之间；
- 回归：全量 `python tests/run_all.py`。

**未验证**：K 线缺失订单的真实展示（只能验证到"—"占位，取决于采集）；52 周口径若产品要求改为"250 个交易日"需另立变更。

## 6. 实施说明

- 模型 `StockKline.get_low_52w_batch(ids)` 一次 `GROUP BY` 取回本页订单；列表原有的"逐行取 K 线信号"是 N+1，本次**不叠加**同类问题，也**未顺带改造**它（超出本次范围，记为已知限制）；
- 无数据渲染 `—`，不渲染 `0.00`——后者会被误读成"股价为 0"；
- 表格 `min-width` 1060 → 1160，新增列宽 110px。

## 7. 已知限制

- 列表页 `kline_signal` 仍是逐行查询（每页多 10~50 次 SQL），本次未改；如需优化可复用 `get_low_52w_batch` 的批量思路另立变更。
