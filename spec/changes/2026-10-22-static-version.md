# 变更：静态资源加版本号（cache busting）

| 项 | 内容 |
| --- | --- |
| 状态 | **已合入**（需用户刷新一次页面确认） |
| 类型 | 缺陷修复（前端改动不生效） |
| 触发 | 用户反馈：列表页「刷新行情」按钮点了**没反应** |
| 关联规格 | [008 前端 UI](../current/008-frontend-ui.md) |
| 验证 | 全量 **276 用例通过**（新增 `tests/test_static_version.py` 6 个）；真实渲染确认：页面输出 `/static/js/theme.js?v=1792638133`，带 `?v=` 请求返回 200，内容含 `initRefreshQuotes` |

## 1. 根因

Flask 对 `static` 目录的响应**不带明确的 `max-age`**，浏览器走启发式缓存。于是：

- 按钮是**服务端渲染**的 → 用户能看到新按钮；
- 但 `theme.js` 是**旧版本** → 里面根本没有 `initRefreshQuotes` → 点击无任何处理函数 → "没反应"。

影响面不止这一个按钮：此前几轮的前端改动（实时系统状态轮询、表格行淡色底）用户可能都没真正看到。

## 2. 修复

- 新增 `app.static_url(filename)`（`template_global`）：按文件 **mtime** 拼 `?v=<ts>`，文件一改 URL 就变，强制拉新；
  文件不存在时降级返回不带有效版本号的地址（不抛异常，模板渲染不该因缺文件挂掉）；
- `base.html` / `auth.html` / `error.html` 的 CSS 与 JS 引用全部改用 `static_url()`，**不再裸用 `url_for('static', ...)`**；
- 测试锁住：三个模板里不得再出现 `url_for('static'`；渲染出的 `<script>` / `<link>` 必须带 `?v=`。

用户侧：正常刷新一次页面即可（HTML 里的资源地址已变）；保险起见 `Ctrl+F5`。

## 3. 顺带修：刷新行情"看不出变化"

即使 JS 生效，**库里数据常常和页面上已显示的完全一样**（监控线程刚采集过），
数字不动 + 只改 1.5 秒按钮文案，仍然像"没反应"。所以一并提供可见反馈：

- 数值**发生变化**的单元格短促高亮（`td.flash` + `@keyframes flash-cell`，用 `--flash-bg`）；
- 按钮文案区分两种情况：`已刷新 10 条 · 3 项更新` / `已是最新 09:41:05`——
  后者明确告诉用户"数据本来就是最新的"，不会被误认为按钮失效。

## 4. 未验证

- 浏览器里的实际观感（高亮动画强度、文案时长）需用户看一眼；
- 生产部署若走 Nginx 静态目录，应给 `/static` 配 `Cache-Control`，与这里的 `?v=` 配合更稳。
