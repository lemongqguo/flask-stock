## 1. 问题与动机

上一项变更（[2026-10-23 追问 Composer](./2026-10-23-ai-composer.md)）把密钥录入与测试连通性搬进了 Composer，
但**右栏参数卡里的「连通测试」按钮还留着**，于是同一个功能有两个入口、两种叫法：

- 参数卡叫「连通测试」，Composer 里叫「测试连通性」——名字都不统一；
- 且 Composer 里的入口是「密钥 sk-***」文案，从名字看不出它能测连通性，
  用户得先点开才知道里面有个测试按钮。

## 2. 变更类型

- [ ] 缺陷修复
- [x] **行为变更**：连通测试入口由「参数卡 + Composer 两处」合并为「Composer 一处」
- [ ] 纯重构
- [ ] 新增能力

## 3. 旧约定 → 新约定

| 项 | 旧约定 | 新约定 |
| --- | --- | --- |
| Composer 的密钥入口 | pill 文案「密钥 sk-***23」+ 锁图标 | pill 文案**「测试连通性」** + 刷新图标，点它展开密钥面板 |
| 密钥脱敏值的位置 | 在 pill 上（工具条） | 移到密钥面板顶部（「当前密钥 sk-***23」），工具条只留功能名；顶部 hero 的状态 chip 仍显示脱敏值 |
| 面板里的测试按钮 | 「测试连通性」 | 「用这个密钥测一下」（避免与 pill 同名，语义更明确：测的是刚粘贴的这个密钥） |
| 右栏参数卡 | 「连通测试」按钮 + 「密钥 sk-***23」文本 | **删除按钮**；保留脱敏文本并改为「密钥 sk-***23 · 测试在底部对话框」 |

`/stock/ai/test` 路由与它的三个参数（`api_key` / `model` / `clear_key`）**一律不变**，功能不受影响。

## 4. 影响面

- 文件：`templates/ai_analysis.html`、`static/css/theme.css`（新增 `.ask-key-now`）、`tests/test_ai_analysis.py`；
- 数据表 / 迁移 / 配置 / 路由：**无**；
- 无功能的增删，只是把同一入口从两处收到一处。

## 5. 取舍

1. **pill 用功能名而不是状态名**：pill 点开是"做事"（录入 + 测试），不是"展示密钥"；
   名字写成动作名，用户不点开也知道它能干什么。密钥脱敏值没丢——挪进面板顶部，且顶部 hero chip 仍在。
2. **面板按钮改名而不是删**：pill 只负责展开，真正提交仍需要一个按钮；
   叫「用这个密钥测一下」是为了说清"测的是刚粘贴的这一个"，不是环境变量里的那个。
3. **参数卡的脱敏文本保留并指向 Composer**：删按钮不等于删信息，用户仍能在参数页看到当前用的是哪个密钥。
