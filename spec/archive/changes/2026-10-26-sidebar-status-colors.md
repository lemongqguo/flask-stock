# 变更：侧栏运行状态上色（正常绿 / 异常红）

| 项 | 内容 |
| --- | --- |
| 状态 | **已合入** |
| 类型 | **行为变更**（展示语义：状态色；不改数据、不改路由） |
| 触发 | 用户要求：侧栏底部的「监控 运行中」与「雪球 正常」正常时显示绿色，异常时红色 |
| 关联规格 | [008 前端 UI](../../current/008-frontend-ui.md)（§4.1 侧栏状态）、[004 监控服务](../../current/004-monitor-service.md)（状态来源） |
| 验证 | `tests/test_system_status.py` + 全量 `tests/run_all.py`（见 §5） |

## 1. 问题

侧栏底部 4 行状态（监控 / 交易时段 / 告警冷却 / 雪球）**实际全部是灰色**，看不出健康与否。两个原因叠加：

1. `.side-foot-row b { color: var(--text-2) }`（特异性 0,1,1）**压过了**裸 `.up` / `.down`（0,1,0），
   模板里写的颜色类根本没生效；
2. 即便生效，语义也是**反的**：雪球 `ok` 时挂 `up`——而本项目是「红涨绿跌」，`--up` 是**红**、`--down` 才是绿，
   于是「正常」会显示成红色、「限流退避中」反倒显示成绿色。

## 3. 旧约定 → 新约定

| 项 | 旧约定 | 新约定 |
| --- | --- | --- |
| 颜色语义 | 复用行情类 `up` / `down`（红涨绿跌，语义与"健康"相反，且被行样式覆盖成灰色） | 语义类 `status-ok`（绿）/ `status-bad`（红），配合 `--ok` / `--bad` 别名 |
| 颜色判定位置 | 模板里 `if running` 现算，JS 轮询时再算一次（两处判定会漂移） | **只在 `utils.system_status` 输出 `tone`**（`ok` / `bad`），模板与 JS 只渲染 |
| 监控行 | `down` / `muted` | 运行中 → `status-ok`（绿）；已停止 → `status-bad`（红） |
| 雪球行 | `up` / `down`（反的） | 正常 → `status-ok`（绿）；限流退避 / 未配置 Token / 状态未知 → `status-bad`（红） |
| 交易时段 / 告警冷却 | 灰色 | **刻意保持中性色**：它们是信息不是健康状态，"已收盘"变红会误导 |

`--ok` / `--bad` 是别名：`--ok: var(--down)`（绿）、`--bad: var(--up)`（红）。
不直接写 `up`/`down` 是因为那两个是行情语义，拿 `down`（下跌=绿）当"正常"用，代码读起来像反的。

## 4. 影响面

- `utils/system_status.py`：`monitor` / `xueqiu` 增加 `tone` 字段（`_xueqiu_state` 三个分支都给）；
- `templates/base.html`：两行改用 `status-{{ tone }}`；
- `static/css/theme.css`：`--ok` / `--bad` 别名 + `.side-foot-row b.status-ok/.status-bad`（**必须带前缀**才能压过行样式）；
- `static/js/theme.js`：轮询更新改用 `setStatus()`，颜色随 `tone` 一起更新（否则首屏颜色对、30s 后不对）；
- 数据表 / 路由 / 配置：**无**（`/stock/api/system_status` 多返回一个字段，向前兼容）。

## 5. 取舍

1. **监控"已停止"算异常（红）而不是中性灰**：监控本该在跑，停了就是没在监控，
   用灰色会被读成"暂时没事"；用户也明确说"异常则为红色"。
2. **交易时段与冷却不上色**：只有真正表达"健康与否"的两项才染色，
   否则一栏四种颜色反而看不出重点（"午间休市"既不健康也不异常）。
3. **减掉 `--ok`/`--bad` 一层别名而不是直接写 `var(--down)`**：这一层只为可读性，成本是两行 CSS。
